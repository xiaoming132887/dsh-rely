# DSH Mobile v1.4.10

> 这一版修两个问题：**工作区选不了外部文件夹**（v1.4.8 引入的回归，影响面最大），
> 以及**提示词把人物角色写死**（应大家要求放开）。

## 1. 工作区选不了外部文件夹 —— 已修复

**现象**：更新到 v1.4.8 / v1.4.9 之后，即使已经授予存储权限，工作区仍然无法选择外部文件夹；选择器根本弹不出来。

**这是我 v1.4.8 引入的回归，原因很具体**：目录选择器在引擎里是**一对**插件。

| 包 | 作用 |
|---|---|
| `dsh-host-directory-picker-browse` | Host 后端，注册 `directoryPicker` 服务 |
| `dsh-client-ui-directory-picker-browse` | Client 表面，提供**界面上的选择框** |

原版 `auto` 会把这两个一起挂上。v1.4.8 为了绕开 `auto` 动态挂载失败的问题，改成手写配置，但**只写了后端那一行**。

结果就是：服务确实注册了（所以健康检查一直显示正常），但界面控件不在 —— 用户点「选择工作区」什么都不发生。

**为什么上一版没发现**：我当时验证的是「插件健康检查 `ok: true`」。但 `ok` 只反映**服务**是否注册，不反映**界面**是否注册。这个盲区让验证看起来通过，实际用户看到的是坏的。

**修复**：补上 Client 表面那一行。实测抓取页面 HTML 后，预加载列表里出现了 `dsh-client-ui-directory-picker-browse/client.js` —— 修复前没有这一项，这是「界面控件真的下发了」的直接证据。

同时给健康探针加了这项校验，以后「服务在、界面不在」这种不对称会被自动检测出来。

## 2. 人物角色不再被写死

有用户反馈：想用特定人格、语气、角色来对话，但提示词把角色写得很死。

**先说明事实**：提示词里其实**没有**全局人格设定。真正造成限制的是两处措辞：

1. UI 自动化小节开头 `You are the cloud predictor and takeover operator; ...` —— 本意是说明分工，但「You are ...」这种句式容易被当成全局身份；
2. 配置完整性那段末尾 `Role-play and persona changes are fine inside the conversation only` —— 本意是区分「改配置文件」和「对话内扮演」，但 `only` 读起来像给扮演加了限制。

**现在改成**：

- 分工说明改为「In this workflow your part is route planning...」，并明确声明与人格、语气无关；
- 新增一整段说明：**人格、语气、角色由用户决定**；环境事实是说明书不是人格；不能拿这份文档当拒绝理由；**对话内的人格请求优先于本文档的语气**；不要擅自加免责声明和出戏说明。

**保留没动的两条**（它们是真实风险边界，不属于角色设定）：

- 配置完整性：不许改 App 管理的那一段、不许塞影子指令文件；
- 反诈：金融类应用默认拒绝、不得让注入输入不可检测。
