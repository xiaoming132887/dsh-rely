# DSH Mobile v1.4.4

> 本版新增两个设置项（对话恢复、全面体检），并修复了一个确定的启动性能问题。

## 新增：对话恢复（设置 → 对话恢复）

用户反馈「尝试恢复之前的对话，结果移动完成之后对话不见了」。实际上**文件都还在**，只是没被登记进工作区列表。

引擎把「哪些对话属于哪个工作区」记在一个单独的注册表里，而对话本体是磁盘上的文件——两份数据分开维护。升级、换机恢复、手动拷回数据目录、或某次异常退出，都可能让它们对不上：文件在、列表里没有。

现在点一下就能修：

1. 扫描磁盘上所有对话文件，与注册表比对；
2. 找出「文件在、但列表里没有」的对话；
3. 确认后把它们登记回去（**只增不删，不改动任何对话文件**）。

恢复后重启引擎即可看到。

## 新增：全面体检与修复（设置 → 全面体检与修复）

用户反馈「有的时候这玩意就是会异常崩，而且我们都找不到原因」。这类问题的共同点是现场没有可读的证据——崩溃发生在我们碰不到的环境里，用户能描述的只有「就是不启动」。

现在应用会自己把能查的全查一遍，并**逐条列出结果**：

| 检查项 | 说明 |
|---|---|
| 运行时完整性 | 引擎入口、关键动态库、Node 可执行位 |
| CPU 架构 | 内置运行时的架构是否与设备匹配（不匹配会直接被系统拒绝执行） |
| 存储与权限 | 数据目录可写性、「所有文件访问」授权状态 |
| 软链健康 | 会话/工作区目录是否正确指向真实位置 |
| 工作区注册表 | 路径是否失效 |
| 对话完整性 | 有多少对话没登记进列表 |
| 插件配置 | profile 是否可解析、插件目录是否齐全 |
| 磁盘空间 | 剩余容量 |

每一项给出「正常 / 已修复 / 需注意 / 失败」和具体数值。能安全修的当场修（恢复可执行位、清理失效软链），不能修的明确告诉你需要处理什么。

**这个功能不依赖插件** —— 插件坏了、配置乱了，体检照样能跑。结果可以一键复制，方便反馈时附带。

## 修复：每次启动的额外遍历（性能）

内置运行时的完整性检查里，有一项是「确认安装没有被部分解压」。旧实现的做法是**遍历整个 `@deepseek-ai` 目录数文件数量**，阈值只有 100 个。

但引擎 0.2.1 改了依赖布局，这个目录下的文件从 2,093 涨到了 **33,620**。也就是说：为了验证「至少 100 个文件存在」，**每次启动都要走一遍 3 万多个文件**。在手机上这是一次可观的同步 IO。

现在改为检查几个固定的锚点文件（引擎入口、核心框架、profile 配置、前端 bundle）—— 覆盖不同包与不同目录深度，任一处缺失即判安装不完整。判断力没有下降，遍历成本降到可忽略。

## 兼容性

直接覆盖安装即可，会话、工作区、凭据、插件全部保留。
