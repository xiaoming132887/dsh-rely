# DSH Mobile v1.4.16

> 这一版包含两部分：**插件兼容性大改**（装前检测 + 崩溃自愈），以及一轮**全面代码审查**后
> 修掉的 3 个严重缺陷——其中一个会影响"引擎崩溃后自动重启"这个核心能力。

## 1. 插件装不上 / 装完把 App 搞挂 —— 两个都修了

这是很多用户反馈的问题，根因比表面复杂：

**`ERR_PNPM_IGNORED_BUILDS`**：插件中心用的 pnpm 12 默认**拒绝执行**依赖的构建脚本。
带原生模块的插件（better-sqlite3、sharp、node-pty、canvas 这类）会"装成功但二进制没编译"——
你拿到一个装上了却用不了的插件。而在 Android 上这类模块基本都编译不出来。

**装完直接起不来**：坏插件可能让引擎进程在启动时崩溃，而且之前要重试很多轮才能恢复。

### 现在的做法

**装前检测**：点"安装"时先查插件元数据，识别六类原生信号（构建脚本、gyp 项目、
预编译下载、平台变体缺 android、原生依赖等）。命中就先弹窗说明风险，列出具体原因，
你可以选择"仍然安装"或取消。纯 JS 插件（lodash、chalk 这类）直接装，不会误拦。

**崩溃自愈**：装了让引擎起不来的插件，现在连续 2 次启动失败后会自动摘掉
最近安装的那个插件（每次只摘一个、先备份清单），然后引擎自动恢复。整个
过程不需要你做任何操作——实测从注入致命崩溃到自动恢复约 40 秒。

摘掉的插件有完整备份（`plugin-recovery/` 目录下带时间戳），可以恢复。

## 2. 全面代码审查修复的 3 个严重缺陷

这轮审查覆盖了 v1.4.9 以来的所有改动，修掉的问题里有两个值得说明：

**引擎崩溃后不再误判"启动超时"**：之前有个自相矛盾的 bug——引擎健康运行超过
5 分钟后一旦崩溃，第一次自动重试就被误判成"启动超时 N 分钟"直接报错放弃，
自动重启这个核心能力实际是失效的。实测现在强杀引擎 9.3 秒自动恢复。

**CI 构建门禁从未生效**：一个戳文件被误提交进仓库，导致 CI 上的构建校验
（PTC 补丁检查、运行时去重）全程被跳过。已修复——这也意味着从这版起
CI 构建的包和本地构建完全一致。

另外还修了：插件安装/卸载串行化（之前并发装两个插件可能损坏配置）、
快速隔离加了节流上限（防止把无辜插件全摘光）、若干并发可见性问题。

## 3. 此前版本修过的问题（一并包含）

- 启动提速：冷启动 52 秒 → 24 秒（运行时去重），APK 从 241MB 降到 185MB
- 数据导出（设置 → 其他 → 导出数据）
- PTC 模式环境变量补全（28 个，含 git/python/perl/ruby 等扩展工具链）
- 重启后永久卡住、工作区选不了外部文件夹、corepack 入口损坏等
