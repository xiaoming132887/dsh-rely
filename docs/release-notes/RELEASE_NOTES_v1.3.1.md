# DSH Mobile v1.3.1

> 本次是**稳定性版本**：修复终端不可用、横屏启动卡死、以及 Root 模式下「异常退出后二次启动失败」
> 这两个长期反馈。全部修复都经过真实代码路径的端到端验证。

## 终端现在可以用了

此前在 App 内点「新建终端」会直接报错：

```
subprocess-local: command "/data/data/com.termux/files/usr/bin/bash" is not an executable file
```

原因是两层叠加，缺一不可：我们打包的 Node 运行时来自 Termux 官方构建，该二进制把「默认 shell」
**写死**成了 Termux 自己的目录（与用户是否装过 Termux 无关）；而终端真正依赖的 PTY 后端在
Android 上根本没有可用实现（`node-pty` 没有 Android 预编译产物）。

现在：

- 引擎启动时显式注入自带 bash 的路径，彻底绕开硬编码；
- 新增随包分发的**原生 PTY 助手**，并补上运行时对 Android 平台的支持，
  让 Web 终端与 AI 使用的持久 bash 工具都跑在**真实伪终端**上（真机实测 `tty` 返回 `/dev/pts/N`）；
- 关闭终端后子进程被干净回收，不留孤儿进程。

## Root 模式：异常退出后能自己恢复

这是本次最重要的修复。此前在 Root 模式下，如果 App 因为异常原因被杀（被系统清理、崩溃、手动强杀），
**有时会导致之后再也起不来**，用户只能卸载重装。经排查是两条独立成因：

**① 端口被残留进程占住，而自动清场从未生效**

Root 模式下引擎以 root 身份运行，且它的进程挂在 `su` 外壳之下 —— 我们原有的「父进程死亡则子进程跟随」
保护只能挂在 `su` 外壳上，**传不到真正的引擎进程**。因此 App 被强杀时引擎可能活下来、继续占着端口。
更关键的是：此前三轮修复里写的「检测到端口冲突就自动清场」那段代码**从来没有执行过**（判断条件写错，
拿一个哈希值去比对错误字符串，永远不可能匹配）。于是本该自动清场的场景反被当成「配置损坏」，
触发了回滚配置 → 进入安全模式（归档用户配置）→ 最终停止启动 —— 这就是「删掉重装才好」之外的另一种现场。

现在：端口冲突的判定改用硬证据（探测超时按「被占用」处理、只检查本次启动的日志），
清场不再要求「父进程是 1」（实测这类残留进程挂在 adbd 等系统进程下，旧规则必然漏掉），
并明确把**环境类失败与配置损坏分开** —— 端口冲突、su 一时不可用都不会再冤枉你的配置。

**② 文件属性被改坏，App 读不了自己的文件**

Root 引擎创建的文件属主是 root，而 App 自身不是 root，**反而读不了自己的文件**（最先卡住的是版本戳，
App 每次启动都要读）。旧代码只在「非 Root 模式」才做归属修复，Root 模式恰恰跳过；权限位被剥
（例如变成 `----------`）时更是没有任何恢复机制。用户只能靠卸载重装 —— 因为卸载会清空私有目录，
等于把坏属性一起清掉。

现在改成**分层自愈**：

- 先自己修 —— 实测确认「属于 App 自己的文件直接改权限即可，不需要任何特权」，
  因此无 root、无 Shizuku 的设备也能自愈；
- 修不动才动用 su / Shizuku，并顺带重置 SELinux 标签；
- 覆盖所有模式（含 Root），并在重建运行环境前先做一次自愈（否则 root 属主文件删不掉）。

## 其他稳定性改进

- **横屏进入不再卡死**：选择横屏/桌面布局进入时，启动遮罩此前不会消失（挡住整个界面）。
  现已修复，并加了兜底：即使加载异常，遮罩也会自动消失。
- **无人值守自恢复**：端口被残留进程占住时会自动清场重试（有次数上限，
  避免被无关进程永久占用时空转），恢复正常后会记录明确日志。
- **su 探测重试**：App 被强杀后立刻重启时，su 服务可能尚未就绪，现在会等待并重试一次。

## 验证情况

修复均在**安卓 16 与安卓 11** 两个系统的模拟器上按引擎真实启动链路验证：

- 人为制造「残留进程占住端口」→ 自动清场 → 引擎恢复健康，**用户配置零改动**；
- 人为制造「文件与目录权限全部剥除 + 强制杀死 App」→ 检测到损坏 → 自动修复 16806 个条目 →
  引擎正常启动。

## 已知问题

- 设备自带的 Android System WebView 若低于 **Chrome 85**，启动时会提示更新（可点「仍然继续」）。
  这是界面渲染的硬性要求，建议在应用商店更新 WebView。
- 语音输入悬浮框收起时可能有一两帧的视觉残影（不影响功能）。

## 安装

- 覆盖安装即可，无需卸载（数据与配置保留）。
- 若从 Root 模式切回普通模式后遇到异常，本版会在启动时自动修复文件属性，无需手动清理数据。
