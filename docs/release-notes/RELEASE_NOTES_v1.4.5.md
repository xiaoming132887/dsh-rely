# DSH Mobile v1.4.5

> 本版针对「长会话卡顿」（issue #26）补上第二层优化，并包含上一版的对话恢复与全面体检。

## 长会话卡顿：第二层优化

上一版（v1.4.4）修掉的是**我们自己造成的开销**：三个窄屏界面插件此前监听整棵页面树，AI 输出时每帧触发重判，实测产生过 68,502 次样式计算。那部分已经归零。

但 issue #26 的现场还有另一半原因，在**引擎自己的渲染方式**上：

聊天正文是「所有消息行全量渲染」，只有右侧的轮次导航条用了虚拟滚动。一个跑了 300 轮的会话，每轮含思考、工具调用、命令输出，累计上千个常驻 DOM 节点。手机每次重排都要为它们付代价，节点越多越慢——这解释了为什么：

- 新开会话立刻流畅（节点少）；
- 滑动、开侧边栏、呼出输入法都卡（都触发布局重算）；
- 服务端打开会话只要 11ms（不是数据加载问题）。

**本版的改法**：给视口外的消息行加 `content-visibility: auto` —— 浏览器会跳过它们的布局与绘制，滚到视口内时再正常渲染。

这是纯 CSS 优化：
- 不改动任何会话数据，模型上下文完全不受影响；
- 不改 DOM 结构，滚动位置与视觉结果保持一致；
- 不支持的 WebView 会自动忽略这条规则（不会更糟）。

## 一并包含（v1.4.4 的内容）

- **对话恢复**（设置 → 对话恢复）：扫描磁盘上未登记进工作区的会话，确认后登记回去。只增不删。
- **全面体检与修复**（设置 → 全面体检与修复）：8 项检查逐条报告，能安全修的当场修。不依赖插件。
- **启动性能**：移除了每次启动遍历 3 万多个文件的完整性检查，改为固定锚点抽样。
