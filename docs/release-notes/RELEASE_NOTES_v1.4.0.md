# DSH Mobile v1.4.0

> 本次是**引擎换代**：内置的官方 dsh 引擎从 `0.2.0-rc.2` 升级到 `0.2.1-rc.2`（上游 1925 个提交），
> 并附带上一轮发布后完成的稳定性修复。这是继 v1.3.3 之后的**正式版**。

## 本版重点修复

**长会话卡顿（根本原因已定位并修复）**：多位用户反馈会话跑到几百轮后，
滑动、打开侧边栏、唤醒输入法都会明显卡顿。排查后确认**原因在我们自己**——
窄屏适配的三个界面插件都在监听整棵页面树的所有节点变化，AI 输出时消息流
每几毫秒更新一次，导致插件每一帧都要重新判定一次布局；其中设置面板插件在
未打开设置时会扫描全页所有块级元素并做样式计算。

实测同一场景下，插件产生的样式计算从 **68,502 次降到 0 次**，DOM 查询从 164 次降到 0 次。
修复后功能全部保留（原有 94 项界面测试全过）。

**「打开配置文件」现在真能用了（issue #25）**：设置里的这个按钮此前在 Android 上必然失败——
上游把文件交给桌面文本编辑器（macOS `open -t` / Windows 资源管理器 / Linux `xdg-open`），
Android 一个都没有，引擎直接抛「unsupported on android」，界面只显示「无法打开配置文件」，
用户容易误以为配置文件坏了。现在改为打开**应用内编辑页**：可以直接查看、修改、保存，
保存走原子写入并保留原文件权限，写坏配置导致插件被清空的风险不会出现。

**文件面板「资源服务不可用」/ 目录反复刷新（issue #25 后续）**：部分设备（尤其
Android 14 类原生系统）在文件面板里连文件都读不了，或目录列表反复刷新。根因有两层：
应用侧在未获「所有文件访问」权限时误判共享存储可用并建立了软链接；引擎侧的
文件系统层把权限拒绝当成致命错误。两层都已修复：应用侧改为以系统权限状态为准，
并会在启动时自动清理历史遗留的错误软链；引擎侧把权限拒绝降级为「无法观测」。

## 引擎升级到上游 0.2.1-rc.2

上游从 `0.2.0-rc.2` 到 `0.2.1-rc.2` 的跨度不小，其中三处会直接影响 Android 运行层：

- **目录选择器新增 connection 依赖**：上游改动了目录选择服务的依赖声明，并会读取连接信任策略。
- **profile 解析层重构 + 更严格的 Node 内部接口校验**：引擎启动时会检查一批 Node 内部模块接口是否存在，
  不满足就直接拒绝启动。Android 用的是 Termux 构建的 Node，这一层是本轮最大的兼容风险点。
- **子进程 Linux scope 逻辑重构、会话持久化新增并发限制**。

这些改动我们**逐条做了真实验证**，不是静态推断：

| 验证项 | 结果 |
|---|---|
| 双架构 runtime 重新收集（arm64 + x86_64），28 项硬检查 | 全部通过 |
| Android 兼容补丁锚点（13 处）在新版依赖上逐条命中 | 全部命中 |
| x86_64 模拟器：引擎启动 + 关键服务健康标记 | `ok=true`，无缺失服务 |
| x86_64 模拟器：终端真实链路（拉起 PTY、执行命令、回读输出、关闭回收） | 全部通过，`tty=/dev/pts/2` |
| arm64 真机：新版 Node 内部接口校验 | 通过 |
| arm64 真机：覆盖安装后引擎启动 + 健康标记 | `ok=true` |

## 附带修复（上一轮发布后完成）

**「打开配置文件」现在真能打开了（issue #25）**：设置里的这个按钮此前在 Android 上必然失败——
上游把文件交给桌面文本编辑器（macOS `open -t` / Windows 资源管理器 / Linux `xdg-open`），
Android 一个都没有，引擎直接抛「unsupported on android」，界面只显示「无法打开配置文件」，
用户容易误以为配置文件坏了。现在改为打开**应用内编辑页**：可以直接查看、修改、保存，
保存走原子写入并保留原文件权限（`0600`），写坏配置导致插件被清空的风险不会出现。

**插件启动自愈**：如果安装了与引擎不兼容的第三方插件，导致目录选择、工作区等核心能力加载失败，
启动时会检测到并按插件来源精确隔离，**不需要清除数据**。只摘除能精确归因的第三方插件，
保留插件文件与依赖记录以便恢复；连续自动处理有次数上限，无法精确归因时不会擅自改动你的配置，
恢复后会在状态栏提示被停用的插件名。

**窄屏界面性能收紧**：窄屏布局插件此前会观察整棵页面结构的所有属性变化。AI 工作时页面内容频繁更新，
会带来额外的重复布局计算。本版把观察范围收窄到真正影响布局的属性。

**runtime 架构防呆**：安装与构建阶段都会校验内置运行时的 CPU 架构，架构不匹配会给出明确提示，
不再出现「装上就起不来」。

## 兼容性

- 支持**直接覆盖安装**，用户数据（会话、工作区、凭据、插件）全部保留。
- 已安装的第三方插件继续可用；若某个插件与新版引擎不兼容，会在启动时被自动隔离并提示，
  而不是让整个应用打不开。
- 内置运行时同时提供 arm64 与 x86_64 版本，请按设备架构选择（手机一般选 `arm64-v8a`）。

## 已知问题（继续跟进）

- 少数用户反馈的「任务运行中单核占用高」，本地未能复现；本版已收紧一处确定的重复布局开销，
  仍需要更多真实设备的现场数据来定位。
- 设备自带 Android System WebView 若低于 Chrome 85，启动时会提示更新（可点「仍然继续」）。
- 语音输入悬浮框收起时可能有一两帧视觉残影（不影响功能）。
