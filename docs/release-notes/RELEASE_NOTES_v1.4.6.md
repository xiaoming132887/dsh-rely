# DSH Mobile v1.4.6

> 本版是一次系统性代码审查后的批量修复。三个独立审查覆盖了存储/启动/进程/插件/UI 五个模块，
> 共修复 15 项确定缺陷，其中 4 项会直接导致「数据看起来消失」或「引擎永久不启动」。

## 最关键的三项

### 1. 文件系统「有时突然不可用」——真凶找到

用户反复反馈：本来好好的对话和工作区，某次启动后突然全没了、选择工作区报 `directoryPickerController is unavailable`，重启几次又好了。

根因是软链被**误删**。应用为了「卸载不丢数据」把 `sessions/workspaces` 软件链接到共享存储，而旧代码在三个地方会因为**瞬时探测失败**就删掉软链：

- 存储写读探针失败时（FUSE 抖动、MediaProvider 正在索引、开机初期）
- 公共目录探测失败时
- 「全面体检」功能里，目标暂时不可达就删链

删链之后，目录指回**空的私有目录**——用户看到所有数据消失，而数据其实一直躺在共享存储里。下次启动探针又成功了，所以表现为「时好时坏」。

**现在的原则变了**：从「探针能不能通过」改成「数据在不在」。目录存在就保留链接，探针失败只记日志，不再拆链。

### 2. 引擎永久不启动——`userStop` 标志死锁

服务被动销毁（OEM 清后台、系统回收前台服务、划掉任务）时，旧代码把 `userStop` 置为真。而这个标志会阻止所有自动拉起路径——引擎从此再也不启动，直到用户手动点「重启」。用户感知是「打开 App 也不转」。

现在把「用户主动退出」和「本次要停止循环」拆成两个独立标志：只有用户点通知栏「退出」才真正 latch。

### 3. 无限重启风暴

端口被外来进程占用时，清场计数在 0..8 之间循环、退避永远停在 0~2 秒，`MAX_RESTART` 永远到不了 —— 结果是「每 2 秒 spawn 一次 node、立刻死」的永久循环，耗电发热且永不进 Failed。现在改为生命周期内累计，额度用尽直接进 Failed 并给出可读原因。

## 其它修复

### 插件被误判、被摘掉

插件健康探针在等待超时后**无条件判定失败**。但引擎的插件加载是异步的 —— 超时那一刻仍在加载的插件，看起来就是「失败」。慢设备上正常插件因此被判失败并被自动隔离，用户看到「装插件后重启显示加载失败」。

现在超时后仍报告当前状态，但把仍在加载的插件归入 `pending`，不参与失败判定、不被隔离。

### 数据安全（4 项）

- **迁移会删掉软链正在指向的目录** → 本次启动拿到悬空链。现在检测到「链当前指向 legacy」时只复制、不删除来源。
- **遍历与删除会跟随软链** → 走 `deleteRecursively` 时把链**指向的外部文件**一起删掉。现在统一改用不跟随软链的安全遍历/删除。
- **空目录不迁移** → 空工作区被当成「迁移完成」后删除。现在目录也会被创建与校验。
- **注册表写入可能让引擎起不来** → 工作区表存在但顺序表为空时，引擎会直接抛错。现在写回前补齐顺序表。

### 启动与终端

- **`.bin` 目录的可执行位从没被设置过** —— 过滤条件是 `/bin/`，匹配不到 `/.bin/`。当前运行时里有 12 个 `.bin` 条目（`.bin/dsh`、`.bin/cordis` 等），任何直接执行它们的路径都会失败。
- **token 提取用字节偏移当字符下标** —— 日志含中文时偏移错位，token 取不到 → WebView 加载裸地址 → 401/白屏，且重试 6 次用同一个错误偏移必然失败。

### 渲染与界面

- **`contain-intrinsic-size: auto <length>` 需要 Chrome 98+**，而本应用最低支持 Chrome 85。在 85–97 上该声明整体失效，被跳过的行按高度 0 计算 → 滚动条剧烈伸缩。现在两级降级：先写单值形式（85 起可用），再写 auto 形式。
- **设置面板预判过宽** → 页面上存在任意对话框（用量统计、上下文计量等）都会触发全页扫描。现在优先认引擎打的稳定属性 `data-shortcut-modal="settings"`，退路也要求对话框内含导航栏。

### 对话恢复（本版修正后真正可用）

上一版的恢复功能有严重缺陷：拿不到会话的真实工作目录，导致所有会话被塞进第一个工作区；而引擎会按目录过滤，**用户看到「已恢复 N 个」，重启后一个都没有**。更糟的是这些 id 已写进注册表，下次扫描认为「已登记」，永久无法自愈。

现在从引擎自己的投影缓存读取真实目录，拿不到就跳过（宁可少恢复，不可错归）。

### 体检准确性

- 「发现 0 个问题，已修复 1 个」—— 没做任何修复却报已修复。现在改为「待修复」。
- 内置插件目录检查必然误报（查错了目录）。
- 体检不再删软链，只报告。

### 诊断脱敏

插件错误详情现在会截断到 2KB 并遮蔽密钥（`sk-`、`ghp_`、长十六进制、`api_key: xxx` 等形态），避免用户导出日志反馈时意外泄露。
