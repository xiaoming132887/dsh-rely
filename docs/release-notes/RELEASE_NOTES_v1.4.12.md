# DSH Mobile v1.4.12

> 这一版有两件大事：**启动快了一倍**（52 秒 → 24 秒），以及**数据导出**功能
> （社区贡献者 @henryz78 的第二个 PR）。

## 1. 启动速度：52 秒 → 24 秒（-55%）

有用户反馈「1.4 升级之后启动怎么优化都慢，低性能手机宁愿退回 1.3」。查下来**不是上游代码变慢，是我们的打包方式退化了**。

上游 0.2.1-rc.2 把依赖布局从「扁平提升」改成了「逐包嵌套」—— 结果**每个 `@deepseek-ai` 包里都嵌了一份完整的 zod**（612 个文件的完整副本）。全库总共 **30,681 个冗余文件**：

| | 文件数 | 解压后体积 |
|---|---|---|
| 1.3（0.20 引擎） | 13,656 | 377 MB |
| 1.4（0.21 引擎，未去重） | **45,244** | **697 MB** |

文件数是 3.3 倍。冷启动那 42 秒基本都耗在给这 4.5 万个文件做 open/write/close。

更要紧的是：**去重脚本和产物其实早就做好了，但构建脚本一直没引用**。所以我们一直在发带 3 万份冗余文件的包。

### 实测对比（模拟器冷启动）

| 运行时 | 解压耗时 | 引擎就绪 | **总计** |
|---|---|---|---|
| 未去重（之前的 1.4） | 41.99s | 9.78s | **52.17s** |
| 去重后（本版） | **11.81s** | 4.64s | **23.63s** |

去重后连「等健康检查」都从 9.8 秒降到 4.6 秒 —— 模块解析的嵌套层数变浅了。

**APK 也从 241 MB 降到 185 MB。**

> 说明：我用的是「只合并冗余副本」而不是「删类型声明和源码」的方案。后者还能再快几秒，但全库有 773 处配置指向那些文件，用户插件做类型校验时会缺文件 —— 不值得。

## 2. 数据导出（社区贡献 @henryz78）

**设置 → 其他 → 导出数据**，把对话、工作区和工作区列表打包成 `.zip`，存到你选的位置。

包内容：

```
manifest.json                 版本、导出时间、各目录文件数
sessions/...                  对话
workspaces/...                工作区文件（含空目录）
storages/workspace.json       工作区注册表
```

**不包含**：API 密钥与登录态、服务商/模型配置、社区插件、已安装的扩展、`node_modules`。恢复后需要重新登录和重新配置。

设计上几个刻意的选择：

- **不跟随符号链接** —— 只统计跳过数量，绝不把链指向的外部内容打进包；
- **失败就整体失败**，不产出「看起来成功、其实缺一半」的备份；失败时会删掉半成品文件；
- **危险场景会明确报错**：比如工作区目录指向一个不存在的位置时，直接提示「points to a missing location」，而不是导出一个空备份；
- 每一步都写 `engine.log`（`[export]` 前缀），出问题可以直接定位。

实测验证过：中文文件名、空目录、多层 `node_modules`、目录软链、文件软链都正确处理；悬空软链会失败且无残留文件。
