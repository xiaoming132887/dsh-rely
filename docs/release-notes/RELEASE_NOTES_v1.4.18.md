## 插件系统三连修复

### 1. 安装报 `ERR_PNPM_STORE_DIR_OPEN_OPERATION_LOCK` 自动自愈

pnpm 的锁目录（`.cache/pnpm-*`）属主损坏时（Root 模式残留属主、或安装中途被杀
留下悬空锁），此后**每次安装/卸载都必失败**。现在安装/卸载失败命中该错误签名时
自动清理损坏的锁缓存并重试一次——普通死锁直接删；Root 残留的删不动就改名绕开
（pnpm 只按固定名找锁，下次自动重建）。全程用户无感。

### 2. 插件升级不动（新增长期缺失的升级路径）

之前已安装的插件无法升级：按钮只有「卸载」，而且 pnpm 12 下重复安装、`@latest`
安装全部被静默跳过（保留旧版本）。实测矩阵后采用**唯一有效路径——精确版本安装**：

- npm 上有新版时，已安装插件的按钮变为琥珀色「升级」，点击即升到最新版；
- 首次安装也改用精确版本，卸载残留的锁文件不再导致装回旧版。

### 3. 终端启动报 `bash.bashrc: Permission denied`（issue #38）

Termux 构建的 bash 把系统 rc 路径焊死在编译期（无环境变量旁路），装了 Termux 的
设备上终端每次打开必报错。已把该路径等长修补为 `/dev/null`——终端启动干干净净。
`pkg` 命令（Termux apt 体系，本 runtime 必然失败）替换为友好指引：请用 npm/pnpm
或应用内插件中心。

## 内置 SSH 远程工作区插件 0.2.10（@tiphareth/dsh-hardssh）

本地工作区目录弹窗按 DSH 设计语言重绘：路径输入组、快捷入口胶囊、面包屑、
线性图标、固定底栏；并新增「新建文件夹」。插件由 CI 从上游固定提交构建，
随 runtime 发布。
