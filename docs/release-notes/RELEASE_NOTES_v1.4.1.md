# DSH Mobile v1.4.1

> 紧急修复版：解决「通知栏退出后 App 不结束、root 模式持续空转」的问题。

## 本版修复

### 通知栏「退出」现在会真正结束 App

用户反馈：从通知栏点「退出」后，引擎确实停了，但应用本身没有退出，
root 模式下后台持续空转、明显耗电。

排查发现是**三个独立缺陷叠加**的结果：

**① 保活看门狗会把引擎重新拉起来（主因）**

无障碍服务里有一个保活看门狗，每 60 秒检查一次引擎前台服务，掉了就拉起来。
代码注释写着「除非用户显式退出过」——**但这个判断从来没有被实现**。
无障碍服务是系统级组件，App 主进程结束后它依然存活，于是：

```
退出 → 60 秒后看门狗发现引擎不在 → 重新拉起 → 再退出 → 再拉起 ……
```

root 模式下每次复活都要经 su 拉进程，空转代价更高。

**② Activity 已被回收时，退出没有任何收尾**

退出回调注册在主界面上，并在界面销毁时清空。如果用户先按 Home 让界面被系统回收，
再从通知栏点退出，回调已经是空的 —— 代码直接返回，**没有任何东西去结束 App 进程**。

**③ 孤儿进程清理被端口检查挡住**

引擎退出时本会清理残留子进程，但清理逻辑以「端口是否仍被占用」为前提。
主引擎退出后端口已释放，而它派生的后台进程仍在跑，端口检查看不到它们，整条清理被跳过。

### 修复内容

- 新增**跨进程存活**的「用户已退出」标记：退出时写入，下次主动打开 App 时清除。
  看门狗同时检查内存状态与该标记，退出后不再复活引擎。
- 退出流程无条件收尾：界面还在就先关闭界面，随后**结束应用进程**
  （连同前台服务、无障碍绑定、悬浮窗一并释放）。
- 显式退出时**无条件**执行孤儿进程回收（root 模式包含特权视角扫描）。
  只清理命令行里带本应用路径的进程，不会影响你在 Termux 里自己跑的东西。

### 验证

- 退出状态机 4 个场景全部通过，其中包含「退出后 5 分钟内不再复活」的回归验证。
- 编译通过，arm64 release 包签名与架构校验通过。

## 兼容性

- 直接覆盖安装即可，会话、工作区、凭据、插件全部保留。
- 如果你之前遇到过「退出后手机发烫/耗电」，本版应当解决。
- 若退出后仍发现异常占用，请附上设备型号、权限模式与复现步骤反馈。
